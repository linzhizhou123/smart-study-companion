一、赛题到底要我们做什么

数据（输入）

赛题组锁定：40名模拟学生、806条作答记录、54道赛题、两个测验节点（N01上学期、N02下学期）、三个数学主题（T01代数式、T02方程、T03不等式）、8份教材切片、2022版课标PDF。

三项任务（输出）

① 内容梳理：课标→教材→题目三者关联
② 学情分析：个体+群体+评分点级精细诊断
③ 学习建议：具体题目编号+理由+分步提示+先后顺序

核心命题：赛题把数据锁死、技术栈不限制——竞争点不在"用了什么模型"，而在对这套数据的理解深度和交付结果的质量。

三、规则引擎 vs LLM · 精确分工

🔒 规则引擎 / pandas 负责（100%确定性）

  • ✅ 数据清洗、评分点解析、修订版本处理
  • ✅ 计算得分率、主题/指标/评分点聚合
  • ✅ 决定推荐哪道题、什么顺序（必须可追溯到具体题）
  • ✅ 识别"系统性薄弱点"（同一知识点多题丢分）
  • ✅ 识别"记录不足"并生成补充观察建议
  • ✅ 班级统计、两班对比、相关性计算
  • ✅ 知识图谱构建、前置依赖排序
为什么不调LLM？ 赛题评分要求"结果准确、依据充分"——规则引擎的每一个结论都有精确的数据支撑，LLM的"幻觉"在这里是致命风险。

🤖 LLM（文心一言 API）负责（灵活性）

  • ✅ 把结构化诊断翻译成自然语言（像真老师说的话）
  • ✅ 把建议润色成分步启发式提示语
  • ✅ 交互式追问（"为什么这么判断？"）
  • ✅ 用户提反馈后的建议调整对话
  • ✅ 把JSON数据组织成通顺的课堂讲解
为什么要调LLM？ 规则引擎输出的是冷冰冰的JSON——智能体的"智能体感"来自LLM把这些结果变成人类自然语言，并支持交互式对话。
一句话概括： 规则引擎是"脑"（想清楚、算准确），LLM是"身"（说出来、聊起来）。脑不能让身胡说，身也要让脑被听懂。

四、三大核心模块详解

模块A · 学科知识图谱（一次性构建）

构建逻辑

从 CSV 直接解析出 主题 → 指标 → 教材页码 → 赛题题目 → 评分点 五级映射。关键的创新点是给每个评分点硬编码"知识点标签"（如 Q015P3 → "负号去括号后的结果符号"）。这些标签是后续评分点级精细诊断的基础。

硬编码依赖关系

T01I1（数量关系）→ T01I2（同类项）→ T02I1（解方程）→ T02I3（应用题）→ T03I1（解不等式）
这个依赖链用于规则引擎排序建议的先后顺序。

模块B · 学情诊断引擎（核心创新区）

四级聚合粒度

① 学生×节点×主题 → 主题得分率
② 学生×节点×指标 → 指标得分率
③ 学生×节点×评分点 → 知识点得分率 ← 最大差异化机会
④ 评分点跨题目聚合 → 识别"系统性薄弱点"

"记录不足"的正确处理

赛题明确考这个。规则：
已评分且得分低 → 真薄弱
未作答 / 待评分 → 不算"不会"，算"记录空白"
某指标只答过1道题 → 标注"记录不足，暂不能确定"，建议补充观察

模块C · 学习建议生成（规则驱动，不调LLM）

步骤做什么输出
Step 1从诊断结果中按优先级排序薄弱点🔴高 → 🟡中 → 🟢低
Step 2每个薄弱点在知识图谱中找对应题目，按难度递增Q010(基础) → Q015(综合) → Q009(变式)
Step 3根据前置依赖规则，确定建议先后顺序先补T01I2再练T02I1
Step 4记录不足项生成"补充观察建议"（不是补弱建议）"补做Q022，判断真实水平"
Step 5每条建议附带分步提示语（启发式，不直接给答案）"注意括号前的负号..."

五、差异化竞争点（脱颖而出的关键）

P0 · 最大差异化

① 评分点级精细诊断

不是算"整式化简得分率40%"，而是说"负号去括号后的结果符号在Q015、Q018、Q022三次全部丢分"——精准定位到具体知识点。

普通做法: "整式化简弱"
我们的做法: "整式化简中的符号处理完全没掌握，但去括号法则和系数合并都没问题"
P0 · 赛题明确考察

② "记录不足"的诚实处理

明确区分三种状态：已评分低分=薄弱；未作答/待评分=记录空白；答过但≤1道题=不足。绝不把"没记录"说成"不会"。

✓ "D07的T02I3（方程建模）只有1道题的作答记录，不足以判断真实水平"
✗ "D07不会列方程"
P1 · 让建议逻辑严谨

③ 交叉关联诊断

发现跨主题的连锁反应：D15的T02I3（方程建模）差 → 根因是T01I1（字母表示数量关系）没学好。建议顺序：先补根因 → 再练症状。

40个学生的 T01I1得分率 vs T02I3得分率 相关系数 > 0.7 → 确认前置关系
P1 · 赛题明确考察

④ 建议的可执行性 + 不直接给答案

每条建议有：具体题目编号、教材页码、分步启发式提示语、完成条件、后续调整方案。提示语用引导性语言，绝不出现"答案是xxx"。

✓ "注意括号前是负号时，括号内每一项都要乘以-2，特别关注-2乘以-3这一项"
✗ "答案是-4a+6"
P2 · 洞察学习过程

⑤ 修订版本追踪

分析"改了几次改对"、"从哪一步开始改"、"改了还是错"。揭示学生的学习速度和具体障碍点——这是大多数队伍会忽略的维度。

"D07改Q015一次就对了，但Q009改了3次还是2分 → 能修正单点失误，不能处理复合障碍"
P2 · 体现数据理解深度

⑥ 节点间纵向分析

利用 N01（只教T01+T02一元一次方程）和 N02（复习T01+新增T02方程组+T03不等式）的教学进度差来解释"为什么这个指标进步了/退步了"。

"D01的T01I1从80%提高到90% → 复习确实有效"
"D10从60%降到40% → 可能因为新学T03分散了注意力"

六、LLM 接入点详解（文心一言 API）

接入位置

四个调用点，全部在 src/llm_formatter.py 里：

位置输入输出
Formatter #1诊断 JSON自然语言诊断报告
Formatter #2建议 JSON自然语言建议 + 润色提示语
Interactive用户追问 + JSON对话式回答
Adjustment用户反馈 + 建议调整后的建议

API 规范

平台：百度千帆大模型平台
模型：ernie-4.0-turbo-128k（中文好、性价比高、长上下文）
鉴权：API Key + Secret Key → access_token（缓存1个月）
调用频率：批量生成40人报告 ≈ 80次 LLM 调用（一次性跑通）
Key 管理：从环境变量读取，不硬编码

Prompt 模板示例（Formatter #1 · 诊断转自然语言）

def format_diagnostic(diagnostics_json: dict, llm_client) -> str:
    """把规则引擎产出的结构化诊断转成自然语言报告"""
    prompt = f"""你是一名七年级数学教育专家，正在为一名学生生成学情诊断报告。

**核心要求：**
1. 诚实优先：数据不足就说"暂不能确定"，绝不猜测
2. 定位具体：不说"整式化简不好"，要说"在负号去括号这一点上，三次全错"
3. 用老师的语气：像班主任谈话，自然专业不生硬
4. 结构清晰：先总结 → 再分点说发现 → 最后说需要观察的地方
5. 不超出数据范围：每一个"问题"必须有数据支撑

**结构化数据：**
{json.dumps(diagnostics_json, ensure_ascii=False, indent=2)}

请生成诊断报告："""
    return llm_client.chat(system_prompt="你是一名七年级数学教育专家...",
                                  user_content=prompt)

七、技术栈与依赖

核心（必须）

  • Python 3.11+ — 主语言
  • pandas + numpy — 数据清洗、聚合、统计
  • pdfplumber — 教材切片文本提取（预处理一次即可）
  • requests — HTTP 调文心一言 API
  • openpyxl — 读取 Excel 索引文件

不使用（明确排除）

  • 🚫 LangChain / LangGraph — 不用通用 Agent 框架
  • 🚫 向量数据库（Chroma / FAISS）— 赛题范围固定，规则引擎足够
  • 🚫 通用大模型端到端 — 结果不可控，评审要证据
  • 🚫 前端框架（React/Vue）— 赛题不需要实时交互界面
